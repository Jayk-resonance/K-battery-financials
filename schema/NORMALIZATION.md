# 정규화 규칙 (스키마 v2)

모든 인제스트·분석 프로젝트가 따라야 하는 표준. 원문 충실도(as-reported)를 유지하면서 교차 비교를 가능하게 하는 두 개의 정규화 축을 정의한다.

## 1. 사업부문 표준화 — `segment_std`

원칙: **각 리포트가 준 가장 세밀한 단위 그대로 저장**하고(원문 `segment` 보존), 위로 합산 가능한 계층에 매핑한다. 합본으로만 준 것을 쪼개지 않는다(숫자 창조 금지).

```
전사                      # 회사 전체 (SK이노베이션 연결 포함)
├─ 배터리합계              # 전지사업 전체 (삼성SDI '전지', SK온 '배터리')
│   ├─ 소형               # 원통형/소형전지(IT)
│   └─ 중대형             = EV + ESS
│       ├─ EV            # 자동차전지
│       └─ ESS
├─ 전자재료               # 삼성SDI만
└─ (AMPC는 부문이 아니라 metric으로 처리 — 아래 2절)
```

매핑표:
| 원문 부문 | segment_std |
|---|---|
| LGES 자동차, EV | EV |
| LGES/공통 ESS | ESS |
| LGES 중대형, 삼성SDI 중대형전지(EV,ESS), 2차전지(EV+ESS) | 중대형 |
| LGES 소형/원통형, 삼성SDI 소형전지(IT), 2차전지(IT) | 소형 |
| 삼성SDI 전지, SK온 배터리 | 배터리합계 |
| 삼성SDI 전자재료 | 전자재료 |
| SK이노베이션 연결전사, 각사 전사 | 전사 |
| 그 외 (윤활유, 석유개발 등 비배터리) | 기타 |

비교 규칙: 3사 교차 비교는 **공통으로 존재하는 가장 굵은 레벨**에서 한다.
- 배터리합계 레벨 → 3사 모두 가능 (LGES·SDI는 소형+중대형 합산)
- EV/ESS 분리 레벨 → 분리 공시한 증권사만 참여 (합본 리포트는 자동 제외, 억지 배분 금지)

## 2. AMPC 표준화 — `ampc_basis` + metric `AMPC`

문제: 증권사마다 (a) 부문 영업이익에 AMPC를 포함/제외, (b) LGES는 2026년부터 매출에도 AMPC 반영, (c) AMPC를 EV/ESS로 쪼개 공시하기도 함.

원칙: **AMPC는 항상 별도 행(metric=AMPC)으로 저장**하고, 모든 매출·영업이익 행에 `ampc_basis` 플래그를 붙인다.

| ampc_basis | 의미 |
|---|---|
| `excl` | 이 행의 값은 AMPC 제외 |
| `incl` | AMPC 포함 (같은 단위의 AMPC 행이 있으면 차감 가능) |
| `incl_unknown` | AMPC 포함이지만 금액 미공시 → 차감 불가, 비교 시 각주 경고 |
| `na` | 해당 없음 (AMPC 행 자체, 전자재료 등) |

**판정 예시 (인제스트 시 가장 자주 틀리는 부분)**

| 리포트 표기 | ampc_basis | 비고 |
|---|---|---|
| "영업이익 (AMPC 포함)", "OP(incl. AMPC)" | `incl` | |
| "AMPC 제외 영업이익", "OP ex-AMPC", "실질 영업이익" | `excl` | |
| 표에 영업이익과 AMPC가 **각각 행으로** 있고 합계 언급 없음 | 검산으로 결정 | 영업이익 − AMPC 가 다른 표의 '실질 OP'와 맞으면 `incl` |
| "AMPC 반영 시 흑자전환" 식 서술만 있고 금액 미공시 | `incl_unknown` | 차감 불가 → 비교에서 각주 처리 |
| AMPC 행 자체 (`metric=AMPC`) | `na` | 부문이 아니라 지표다 |
| LGES 1Q26~ **매출** 행 | 회사 IR 회계변경으로 매출에 AMPC 병합 → **매출에도 basis 표기** | 3사 매출 비교는 `excl` 기준이 기본 |

- 애매하면 `incl_unknown`으로 두고 넘어가지 말 것 — 그 리포트는 비교에서 빠진다.
  리포트 안에 검산 가능한 숫자(전사 OP, AMPC 금액)가 있으면 **대조해서 확정**한다.
- 실적이 확정된 기간은 뒤에 나오는 `KNOWN_OP_BASIS` 자동 교정이 한 번 더 걸러준다.

파생 지표 (인덱스에 저장하지 않고 분석 시 도출):
```
영업이익_excl = ampc_basis=excl ? 값 : 값 - AMPC(동일 company/segment_std/기간)
매출_excl   = 동일 규칙 (LGES 2026+ 매출에 주의)
```
**3사 비교의 기본(default) 지표는 excl-AMPC 기준.** as-reported와 AMPC 기여분은 별도 레이어로 표시한다.

**표기 오류 자동 교정 (v9)**: 실적이 확정된 기간(예: FY2025, 1Q26)의 영업이익 추정 행은
리포트가 뭐라고 표기했든(incl_unknown/na 포함) 숫자가 실적의 incl/excl 어느 쪽과 일치하는지로
`build_dashboard_data.py`의 `KNOWN_OP_BASIS` 테이블이 basis를 바로잡는다(허용오차 ±20억원).
새 실적 발표 시 그 테이블에 한 줄 추가하면 이후 인제스트분도 자동 교정된다. 원본 인덱스는 수정하지 않는다.

## 2-2. 부문·AMPC 집계 규칙 (분석 단계 — 코드가 강제)

인제스트가 §1·§2를 지키면, 아래 집계는 `build_dashboard_data.py`가 **결정적으로** 수행한다.
인제스트하는 쪽은 이 규칙을 직접 계산할 필요는 없지만, **왜 이렇게 저장해야 하는지**를 알아야
`segment_std`·`ampc_basis`를 올바르게 붙일 수 있다.

**(a) 부문 컨센서스 집계 4원칙**
1. 부문 영업이익은 **excl-AMPC 행만** 사용한다 (분리 불가 리포트는 제외 — 억지 배분 금지).
2. **하우스당 그 기간 최신 리포트 1건만** (1하우스 1표). 같은 증권사가 여러 번 냈어도 최신만 센다.
3. **레벨 혼합 금지** — EV/ESS를 분리 공시한 하우스와 '중대형'으로 합본한 하우스는 **각자 레벨에서만** 집계한다. 합본을 EV/ESS로 쪼개지 않는다.
4. 중앙값을 기본값으로, 평균을 병기하고, **참여 하우스 수 `n`을 반드시 표시**한다.

**(b) AMPC 포함 영업이익(`op_incl`) 파생 우선순위** — 리포트 내에서만 조합한다(교차 리포트 금지)

| 순위 | 조건 | 결과 basis |
|---|---|---|
| 1 | `incl` 행이 있음 | `incl` |
| 2 | `excl` 행 + 같은 리포트에 AMPC 금액 있음 | `derived(excl+AMPC)` |
| 3 | `incl_unknown` 행 | `incl_unknown` |
| 4 | `excl` 만 있고 AMPC 금액 없음 | `excl_only` → **점도표·아웃라이어에서 제외** (기준 통일 불가) |
| 5 | `na` | `na` |

- 부문 AMPC가 없으면 **같은 리포트의 전사 AMPC로 폴백**한다(`segment_std=전사`일 때만 의미 있음).
- 그래서 인제스트 시 **AMPC 금액을 빠뜨리면 그 리포트는 비교에서 탈락**한다. AMPC는 반드시 `metric=AMPC` 별도 행으로 남긴다.

**(c) 정합성 — "부문 합 + AMPC = 전사"가 성립하지 않는다**

성립하지 않는 것이 **정상이며, 억지로 맞추지 않는다.** 이유:

- 부문별로 **참여 증권사 수(n)가 다르다.** EV를 공시한 하우스 15곳, ESS 12곳, 전사 22곳이면
  각 중앙값은 서로 다른 모집단에서 나온 값이라 합이 맞을 이유가 없다.
- 중앙값은 **가법적이지 않다**(median(A)+median(B) ≠ median(A+B)).
- 부문 미공시분(기타·조정)이 전사에는 포함된다.

따라서 대시보드는 **전사/배터리합계 값을 부문 합산이 아니라 전사 행에서 직접 가져오고**,
차트에 "항목별 n이 달라 전사 ≠ EV+ESS 합일 수 있음"을 명시한다.
**부문 합이 전사와 다르다고 해서 데이터 오류로 판단하지 말 것.**

## 2-1. 지표 표준화 — `metric` (통제어휘)

**동의어가 갈리면 그 리포트의 값이 대시보드에서 통째로 누락된다.** 대시보드·분석은
`매출 / 영업이익 / AMPC` 세 지표만 집계하므로, `매출액`처럼 표기가 달라지면 그 행은 조용히 빠진다.
(실제로 이 문제로 기업 리포트 26건의 매출이 누락됐다가 복구된 이력이 있다.)

허용 어휘: `매출`, `영업이익`, `AMPC`, `순이익`, `지배주주순이익`, `출하량`, `점유율`

| 원문 표기 | 표준 metric | 비고 |
|---|---|---|
| 매출액, 매출액(십억원) 등 | `매출` | |
| AMPC(Tax Credit), IRA 세액공제 | `AMPC` | 금액 자체 (부문 아님) |
| 지배주주순익, 지배순이익 | `지배주주순이익` | |
| 영업이익(AMPC제외) | `영업이익` + `ampc_basis=excl` | 지표명에 basis를 섞지 않는다 |

- 매핑은 `tools/build_indexes.py` 의 `METRIC_STD` 에서만 수정한다 (스테이징 데이터 직접 수정 금지).
- 통제어휘 밖 metric은 인제스트 시 `metric 비표준` 경고가 뜬다 → 동의어면 `METRIC_STD` 에 추가,
  새 개념이면 위 허용 어휘에 추가한다. **경고를 무시하고 넘기면 데이터가 새는 것과 같다.**

## 3. 기간 — `period`

`FY`(연간) 또는 `1Q`~`4Q`(분기), `fy`는 회계연도. 추출 범위: 분기는 1Q25 이후, 연간은 FY2024~FY2028. 리포트 발간일 기준 이미 발표된 분기 값은 애널리스트가 인용한 실적(사실상 actual)이며, 미발표 분기는 추정치다 — 발간일(date)과 대상 기간을 대조해 구분한다.

## 4. Actuals (정답지) 분리

- 회사 IR 자료 원본: `actuals/` (LGES 실적설명회·스크립트, 삼성SDI IR)
- 추출 결과: `index/actuals.csv` — 컨센서스 적중률 계산의 기준값
- SK온은 IR 미보유 → 애널리스트 리포트에 인용된 발표 실적의 중앙값을 사실상 actual로 사용하고 출처를 명시한다.

## 5. 투자의견 표준화

매수/BUY/Outperform → `매수`, 중립/HOLD/Marketperform/Neutral → `중립`, 매도/SELL/Underperform → `매도`. 산업 리포트는 null + `industry_views` 사용.

## 6. 스탠스·이슈 통제어휘

`stance_score`: **-10 ~ +10** (2026-07 스케일 확장, 구버전 -2~+2는 전량 재채점 완료).
채점 기준표(rubric) — 부호는 방향, 크기는 확신·강도:
| 크기 | 기준 |
|---|---|
| ±1~2 | 스치듯 언급된 뉘앙스, 명확한 근거 없음 |
| ±3~4 | 방향성 있는 코멘트, 근거 1개 수준 |
| ±5~6 | 명확한 방향 + 구체 근거(수치·일정·고객사) |
| ±7~8 | 핵심 투자논지 수준의 강한 확신, 추정치에 반영됨 |
| ±9~10 | 극단적 콜 — 목표가 대폭 변경 동반, 구조적 단정 |
| 0 | 중립·양비론 |
이슈 태그: LFP, 46파이, ESS, 북미CAPEX, 수율, AMPC, OEM보상금, 파우치, 전고체, 밸류에이션, 소형전지, 유럽EV, 북미EV, 중국경쟁, 관세, 로봇, 배터리판매량. (신규 필요 시 추가하되 유사어 통합)

- **AMPC vs OEM보상금 구분**: `AMPC`는 미국 정부의 IRA 생산세액공제(정부 보조금). `OEM보상금`은 완성차 고객사(OEM)로부터 수취하는 보상금 — 최소구매 미달·물량 미납·설비·JV 청산 보상금 등 일회성 요인. 한 문장이 두 개념을 함께 다루면 각각 별도 스탠스 행으로 태깅한다(1문장 다중 이슈 = 여러 행). 점수는 그 이슈 관점의 견해로 매긴다(예: 보상금 수취로 손실 완충=긍정, 보상금 소멸·일회성 우려=부정).

산업 리포트는 `industry_views`: {scope(글로벌EV수요/북미ESS/유럽EV/중국경쟁/메탈가격/K배터리 등), fy, metric, value, unit, direction(-2~+2), summary, page} + `top_picks`.

## 7. 중복 리포트 처리

동일 내용의 언어판(영/한) 등 중복 리포트는 이중 집계를 유발하므로 인제스트 전에 걸러낸다.
- **탐지**: `tools/check_duplicates.py` — 같은 (하우스, 커버리지) + 발간일 2일 이내를 후보로 플래그. 신규 인제스트 전 `--new-only`로 실행.
- **판정**: 후보의 제목·첫 페이지를 대조해 내용 동일 여부 확인 (언어만 다르면 중복).
- **처리**: 삭제하지 않는다 — 한국어판 1건만 유지, 나머지는 `archive/duplicates/`로 이동(git mv)하고 manifest 항목에 `duplicate_of: <유지한 report_id>` 기록. `build_indexes.py`가 해당 항목을 인덱스·MD에서 자동 제외한다.

## 8. 산업리포트 스키마 v3 (2026-07)

산업리포트는 `schema_version: 3`부터 industry_views를 용도별 테이블 2개로 분리한다.

### demand_forecasts (정량 수요 전망 — 지역별 수요 View·리비전 트래커의 원천)
`{region, application, metric, fy, value, value_prev, unit, basis, page}`
- region: 글로벌|북미|유럽|중국|한국|기타 / application: EV|ESS|합계 (결합 문자열 금지)
- metric: 수요량(GWh)|판매대수(천대·만대)|성장률(%)|침투율(%)|실적치(발표된 과거 실측)
- **표에 있는 모든 연도를 수집한다** (2023~2035, 중간연도 생략 금지)
- value_prev: 리포트가 '기존 전망 대비' 변경을 명시한 경우의 직전 전망치

### themes (정성 방향성 — 테마 로테이션 맵·논거 대전의 원천)
`{theme(6절 통제어휘), direction(-10~+10, 6절 rubric), bull, bear, summary, page}`
- bull/bear: 그 테마의 강세/약세 논거 각 1~2문장 (한쪽만 있으면 다른 쪽 null)

인덱스: demand_forecasts.csv, themes.csv 신설. 기존 인덱스 무변경(하위호환).
기업 리포트의 industry_views(명시적 산업 전망)는 기존대로 industry_views.csv에 유지.

### 수요 시리즈 분류 (비교가능성 큐레이션, 대시보드 v8)
원문 표를 전부 수집하는 원칙(감사 추적)은 유지하되, 인덱스 생성 시
`tools/demand_curation.py`가 각 (리포트×표) 시리즈에 분류를 부여해
demand_forecasts.csv에 `series_class / series_label / scope_note` 컬럼으로 기록한다.
신규 인제스트도 build_indexes.py를 거치며 자동 분류된다.

| series_class | 의미 | 대시보드 |
|---|---|---|
| 시장전체 | 해당 지역×용도 시장 전체의 연간 수요/침투율 전망 | 기본 표시 |
| 서브세그먼트 | 특정 기술·기업·부분시장 (4680, 소듐이온, 주택용 ESS, 데이터센터향, 침투가능수요 등) | 토글 표시 |
| 시나리오 | 가정 기반 별도 추정 (Model Q 시나리오, 성장률 가정시 등) | 토글 표시 |
| 월간·누적 | 연간이 아닌 월간/YTD 수치가 연도에 매핑된 행 | 토글 표시 |
| 생산능력 | 수요가 아닌 CAPA/필요 생산능력 | 토글 표시 |
| 참고치 | 타사 컨센서스 인용, 신규/누적 기준 불명 등 | 토글 표시 |

- series_label: 같은 리포트 안에서 basis 문자열이 다르게 쪼개진 동일 개념 표의 병합 라벨 (선 연결 키)
- scope_note: 집계 범위가 다른 진짜 View의 주석 (예: '중국 제외') — 제거하지 않고 점선+라벨로 구분
- 대시보드 지표 칩은 수요량·침투율만 사용 (성장률/실적치/판매대수는 CSV에 유지, 표시 제외)
- 분류 규칙·오버라이드 수정은 demand_curation.py에서만 한다 (스테이징 데이터 수정 금지)
